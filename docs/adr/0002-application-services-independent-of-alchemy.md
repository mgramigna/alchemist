# Keep application services independent of Alchemy

Alchemist separates browser-safe domain code, the API application, and the React SPA into `packages/domain`, `packages/api`, and `packages/web`. `@alchemist/domain` contains schemas and pure domain functions, including validation, JSON transformations, and derived night priorities; `@alchemist/domain/rpc` is a subpath export of that same package containing browser-safe RPC contracts, rather than a separate workspace package. Shared code imports neither application implementation nor infrastructure code.

Application services inside `packages/api` own workflows and authorization, with dependencies supplied through Effect layers. Thin RPC handlers delegate to these services. Cloudflare-specific persistence and storage code lives in adapters; services can be exercised with controlled dependencies without running Alchemy or deploying a Worker. The web package consumes the domain package and contracts without importing API implementations.

The infrastructure composition root may use Alchemy's Effect Worker constructor. Root `alchemy.run.ts` assembles the stack; `infra/` declares resources, migrations, secrets, SPA assets, and the Worker that supplies production Effect layers to the API application. Construction resolves configuration and registers deferred bindings; request I/O, session identity and disposable clients belong to each execution scope. Alchemy imports remain confined to this composition root, while application services, HTTP/RPC handlers and domain code stay independent of Alchemy.

Amended after implementing Google authentication: requiring a conventional Worker and handwritten binding interface added wiring without improving service testability. Injectable Effect layers establish that boundary. We now use the documented Effect Worker integration and its D1 SQL layer, accepting coupling to Alchemy's construction/runtime lifecycle in the composition root. Local Worker behavior checks must verify configuration binding, migrations, cookies, assets and request isolation; layer-swapped application tests remain the primary workflow seam. D1 atomic batch constraints and Alchemy-managed migrations from ADR 0001 still apply.

Context: [Repo layout and client/server boundary](https://github.com/mgramigna/alchemist/issues/12).
